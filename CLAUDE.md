# oxidyze

A multi-threaded TCP connect scanner. Rust, Cargo project, **zero external
dependencies** — std only.

Only ever used against hosts and networks the user owns or is authorized to
test. Keep the note to that effect in `--help` and the README.

## Before calling any change done

```sh
cargo test              # must be green
cargo clippy --all-targets   # must be warning-free
cargo fmt --check
```

All three are currently clean. Don't leave them dirty.

## Conventions

- **No new dependencies without asking.** Std-only is a deliberate choice, not
  an accident. The CLI parser in `src/cli.rs` is hand-rolled for this reason;
  reaching for `clap` or `tokio` is a conversation, not a default.
- **Tests live in a `mod tests` at the bottom of each module.** Every pure
  function should have one. Socket-touching tests bind an ephemeral port on
  `127.0.0.1` — never a fixed port, never a real remote host.
- **Regression tests name the original symptom in a comment**, e.g.
  `// Regression: this panicked with "index out of bounds..."`. Follow that
  pattern for any bug fixed from here on: write the failing test first.
- **Comments explain why, not what.** The existing ones flag non-obvious
  ordering and protocol constraints. Preserve them when refactoring — several
  encode facts that are expensive to rediscover (see below).
- Errors are `Result<_, String>` propagated to `main`, which prints
  `error: ...` and picks the exit code. Exit 2 = bad usage, 1 = runtime
  failure. Don't `process::exit` from library modules.

## Layout

| File | Contents |
| --- | --- |
| `src/main.rs` | mode dispatch, output formatting, exit codes |
| `src/cli.rs` | argument and port-spec parsing |
| `src/net.rs` | CIDR math, address helpers |
| `src/scan.rs` | worker pool, port scanning, host discovery |
| `src/dns.rs` | PTR / mDNS lookups, resolver discovery |
| `src/arp.rs` | ARP cache parsing |
| `src/banner.rs` | service banner grabbing, well-known-port guesses |
| `src/table.rs` | text table rendering |

## Constraints that are easy to break

These are load-bearing. Changing them silently breaks correctness.

- **ARP is read *after* scanning, never before.** The TCP connects are what
  populate the OS ARP cache; reading it first yields an empty table.
- **Discovery work is ordered port-major**, not host-major, so the pool stays
  saturated instead of serializing ten probes per host. Preserve this if you
  touch `discover_hosts`.
- **Thread counts go through `scan::effective_threads`.** Never pass a
  user-supplied count straight to `thread::spawn` — that aborted the process
  in the original. Spawn failure must degrade, not panic.
- **CIDR host ranges are lazy iterators.** Never `.collect()` a whole block
  into a `Vec` — a `/0` is ~17 GB. Anything over `net::MAX_AUTO_HOSTS`
  requires `--allow-large`.
- **A refused connection means the host is up.** Only a timeout means absent.
- **Argument parsing fails loudly.** Never `.parse().ok().unwrap_or(default)`
  on user input — that silently swallowed typos in the original.
- **`/31` blocks have two usable addresses** (RFC 3021), `/32` has one.
- In `dns.rs`, following a compression pointer must not advance the enclosing
  record's cursor, and pointer loops are bounded — a malformed response must
  not hang the parser.
- **Banner grabbing (`--banners`) only ever runs against ports the connect
  scan already proved open**, and it's opt-in — it sends a follow-up probe
  (a plaintext HTTP request) to services that don't speak first, which is
  more intrusive than a bare SYN and costs up to two connection timeouts per
  port. Don't make it the default. It doesn't decode TLS, so ports like 443
  fall back to the guessed-name table.

## Platform notes

- Builds and runs on Linux as well as macOS: std-only, zero dependencies,
  and there's exactly one `cfg!(target_os)` branch in the whole codebase
  (the resolver lookup below). Nothing else is macOS-specific.
- macOS reads resolvers from `scutil --dns` first; `/etc/resolv.conf` there is
  generated by configd and is often stale or absent. Linux uses resolv.conf.
- macOS caps per-process threads well below Linux, which is why
  `scan::MAX_THREADS` is conservative at 1024 and workers use 256 KB stacks.
- `arp -a` output shape is shared across macOS/Linux/BSD; macOS omits leading
  zeros in MAC octets, which `arp::normalize_mac` pads. On Linux, `arp` comes
  from net-tools and isn't always installed, so `arp::table()` falls back to
  `ip neighbor` (iproute2) when `arp -a` comes back empty.
